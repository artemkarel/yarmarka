# Ярмарка — мини-приложение Telegram для торговли на ярмарках

Учёт товара под реализацию, инкассаций, взаиморасчётов с продавцами, склада,
мероприятий и точек продаж. Работает как Telegram Mini App.

## Как устроен учёт

- Продавец берёт товар под реализацию по **розничным ценам**. Долг = **50%**
  от суммы взятого (процент настраивается в Ещё → Настройки).
- Каждый день продавец скидывает чек инкассации в чат и вносит **сумму терминала**
  в приложение. К зачёту идёт сумма **минус 2%** (комиссия терминала, настраивается).
- Если терминалом внесено больше долга — баланс уходит в минус: **мы должны продавцу**.
- При возвращении продавец сдаёт товар: **на склад** (нераспечатанное) и **на свою
  полку** (открытое — остаётся закреплено за ним). Всё, что не вернул — продано.
  Возвращённый товар списывает долг по тем же 50%.
- Остаток закрывается **наличным расчётом** (админ, карточка продавца).
- В 20:00 по местному времени продавца бот напоминает про инкассацию,
  если у него есть товар на руках и инкассация за сегодня не внесена.

Чистая прибыль (Аналитика, только админ) = наша доля с продаж − себестоимость
проданного по закупу ± результат инвентаризаций − прочие расходы.
Комиссия терминала на прибыль не влияет — её несёт продавец.

## Роли

| Возможность | Продавец | Кладовщик | Админ |
|---|---|---|---|
| Свой баланс, товар, инкассация | ✔ | — | ✔ |
| Остатки склада (кг, без цен закупа) | ✔ | ✔ | ✔ |
| Приход/выдача/сдача/инвентаризация/остатки | — | ✔ | ✔ |
| Номенклатура, поставщики, документы | — | ✔ | ✔ |
| Пользователи (продавцы/кладовщики) | — | ✔ | ✔ (включая админов) |
| Точки, календарь мероприятий, брони | ✔ | — | ✔ |
| Аналитика оборотов (по ценам продажи) | ✔ | ✔ | ✔ |
| Прибыль, расходы, наличные расчёты, настройки | — | — | ✔ |

Первый зарегистрировавшийся пользователь становится админом (или укажите
`ADMIN_IDS` в `.env`). Роли меняются в Ещё → Пользователи.

## Запуск локально

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env      # вписать BOT_TOKEN
.venv/bin/python run.py   # http://127.0.0.1:8077
```

Для разработки без Telegram: `DEV_MODE=1` в `.env`, открыть
`http://127.0.0.1:8077/?dev=1` (число — любой «телеграм-id»).

Тесты бизнес-логики: `.venv/bin/python scripts/smoke.py`

## Начальные данные

```bash
.venv/bin/python scripts/seed_products.py             # номенклатура (~195 позиций, цены нулевые — заполнить в приложении)
.venv/bin/python scripts/seed_places.py path/to/yarmarki_rossiya.xlsx  # мероприятия и точки
```

## Настройка бота (@BotFather)

1. `/newbot` → получить токен → вписать в `.env` как `BOT_TOKEN`.
2. Кнопка меню и мини-апп настраиваются автоматически при старте сервера
   (если `BASE_URL` начинается с `https://`).
3. Узнать свой Telegram ID: написать боту `/id`.

## Деплой (сервер + HTTPS)

Файлы в `deploy/`: `yarmarka.service` (systemd) и `Caddyfile` (Caddy выдаёт
HTTPS-сертификат автоматически). Приложение живёт в `/opt/yarmarka`, слушает
`127.0.0.1:8077`, Caddy проксирует с домена. Один процесс, база — SQLite в
`data/yarmarka.db` (бэкап = копия файла).

Важно: домен (DuckDNS) должен указывать на IP сервера, а порты 80/443 — открыты.

## Структура

```
app/        бэкенд: FastAPI + бот (long polling) + SQLite
webapp/     мини-приложение (vanilla JS, Telegram WebApp SDK)
scripts/    smoke.py (тесты), seed_products.py, seed_places.py
deploy/     systemd unit, Caddyfile
data/       база SQLite (в git не попадает)
```
